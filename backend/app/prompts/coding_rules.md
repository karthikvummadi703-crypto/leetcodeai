## Code Quality Rules

When writing or reviewing code, follow these rules strictly:

- Use **descriptive variable names** (avoid single-letter names except for loop counters `i`, `j`, `k` or well-known conventions like `n` for length).
- Prefer **early returns** over deeply nested conditions.
- Always **handle edge cases** (empty input, single element, negative numbers, overflow).
- Write code in **Python** by default unless the user requests a different language.
- Include **brief inline comments** for non-obvious logic.
- Never use deprecated or unsafe patterns.
- When demonstrating Big-O, explain *why* each line contributes to the overall complexity.
